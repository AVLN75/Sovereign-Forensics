............................................................................................................................. 18 Summary Cityworks is an enterprise asset management system used to manage, track, analyze, and score your infrastructure assets. Built exclusively on Esri’s innovative ArcGIS technology, Cityworks' GIS-centric platform is focused on enhancing The Science of Where by empowering GIS intelligence for local governments and utilities combining your authoritative asset inventory in a geodatabase with business process applications. For more information, see the Cityworks website. The Cityworks Connectors for GeoEvent Server allows you to connect to Cityworks server to poll for Cityworks work orders as well as send work order requests to an external Cityworks website. NOTE: Authorization is handled by the Cityworks Connectors for GeoEvent Server. However, you will need to work with your Cityworks administrator to create an account before you can use the connectors. Information you will need to obtain from your Cityworks administrator includes:

  • Username—The username used to access data from Cityworks.
  • Password—The password used to access data from Cityworks.
  • URL—The URL of the Cityworks server that is hosting the Cityworks API. Install or Upgrade the Add-on You can add the Cityworks Connectors using either the add-on manager in GeoEvent Manager or you can install them manually. For more information on installing add-ons using either of the two options, see the following topics:
  • Install add-ons using the add-on manager
  • Install add-ons manually If you already have the Cityworks Connectors added to GeoEvent Server, you can upgrade it to a new release using the add-on manager or upgrade it manually. For more information on upgrading installed add-ons, see the following topics:
  • Upgrade add-ons using the add-on manager
  • Upgrade add-ons manually After installing the Cityworks Connectors, see Use inputs in a GeoEvent Service to learn how to create and add and input in a GeoEvent Service. Get Started with the Connectors Two new connectors are created when the connectors are deployed to GeoEvent Server—Poll an External Cityworks Website for Cityworks Work Orders and Send Work Order Requests to an External Cityworks Website. Follow the steps below to configure the new connectors. View the Cityworks Connectors 1. Open GeoEvent Manager and navigate to Site > GeoEvent > Connectors.
  1. Type cityworks to search for the two connectors. Create and configure the Cityworks output When the connector is initially added to GeoEvent Server, it is not connected to your Cityworks account configuration. To download your Cityworks configuration to GeoEvent Server, follow the steps below to create a new output, enter your Cityworks information, and download your Cityworks configuration.
  2. In GeoEvent Manager, navigate to Manager > Outputs and click Add Output.
  3. Choose the Send Work Order Requests to an External Cityworks Website under the Cityworks category.
  4. On the properties page, notice the Configuration Complete parameter is set to No. This indicates that the Cityworks configuration is not downloaded.
  5. To download the configuration, type your Cityworks URL, Username, and Password and click Save. Note that this information is provided by Cityworks. Once saved, your Cityworks work order configuration is downloaded. This may take a couple minutes to complete.
  6. Verify the work order template configuration was downloaded, use any of the following options:
  • Open an existing Cityworks output, the Configuration Complete parameter should be set to Yes.
  • Navigate to the URL below on the GeoEvent Server machine. This page displays your Cityworks work order template IDs (note that you can replace localhost with your GeoEvent Server machine’s fully qualified domain name to access this page from other machines on your network): https://localhost:6143/geoevent/assets/cityworks/WorkOrders.html
  • The GeoEvent Server logs indicate that the configuration is downloaded. With the work order configuration downloaded from your Cityworks account, this information will be utilized by your Cityworks Connector outputs. Configuration details After the Cityworks work order configuration is downloaded by GeoEvent Server, the configuration can be viewed in several locations including:
  • Open and existing Cityworks output, click the Work Order Template parameter dropdown to view the list of cached work order template IDs. This list is available on any Cityworks output if the Dynamic Work Order parameter is set to No.
  • An HTML file is written to GeoEvent Manager that allows you to view all downloaded work orders. This page lists the Domain, the Group - Asset Group, the Entity - Entity Type, the Work Order - Work Order Template Name, and the WOID - Work Order Template ID. You can use the values in this table to configure Cityworks inputs to query specific work order types or use a Field Calculator Processor to set the work order template ID for dynamic work order creation. The web page is found at the link below on your GeoEvent Server machine (note that you can replace localhost with your GeoEvent Server machine name to access this page from another computer on your network): https://localhost:6143/geoevent/assets/cityworks/WorkOrders.html
  • The cached work order IDs are written to the GeoEvent Server data folder under the GeoEvent Server installation directory. For example, on Windows, this folder is found in the following directory location: C:\Program Files\ArcGIS\Server\GeoEvent\data\cityworks

Parameters Below is a description for each of the connector’s parameters. Poll an External Cityworks Website for Cityworks Work Orders The following are the parameters for the Poll an External Cityworks Website for Cityworks Work Orders input. Parameter Description Name A descriptive name for the input connector used for reference in GeoEvent Manager. Refresh Interval (seconds) Specifies how many seconds to wait between requesting an update to the active work orders. The default is 60 seconds. Work Order Template ID(s) A comma separated list of work order template IDs to filter results by. For example: 1425,1799 Asset Group(s) A comma separated list of asset groups to filter the results by. For example: airports,parks Entity Type The entity type to filter the results by. URL The base URL for requesting data from the Cityworks API. This URL is provided by Cityworks. Username The username provided by Cityworks. Password The password provided by Cityworks. Send Work Order Requests to an External Cityworks Website The following are the parameters for the Send Work Order Requests to an External Cityworks Website output. Parameter Description Name A descriptive name for the output connector used for reference in GeoEvent Manager. Configuration Complete? Specifies if the background configuration is complete for this output. The default is No. Options include:
  • Yes— The background configuration is complete, allowing you to specify if a dynamic work order exists or not and a work order template.
  • No—The background configuration is not complete. Dynamic Work Order? (conditional) Specifies if you have a dynamic work order. The default is No. Options include:
  • Yes—Fields in the event data will be used to set the Work Order Template ID value on the new Work Order allowing you to create different work orders using the same output.
  • No—Allows you to select a single, static, work order template ID from a list for all outgoing events. Parameter is shown when Configuration Complete is set to Yes. Work Order Template (conditional) Choose a work order template ID from the list. Parameter is shown when Configuration Complete is set to Yes. Work Order Template Field (conditional) Specifies the field name containing the work order template ID. The default value matches the field value in the GeoEvent Definitions provided with the adapter. Values for the work order template ID can be found at the link below: https://localhost:6143/geoevent/assets/cityworks/WorkOrders.html Parameter is shown when Dynamic Work Order is set to Yes. URL The base URL for requesting data from the Cityworks API. This URL is provided by Cityworks. Username The username provided by Cityworks. Password The password provided by Cityworks. Check for Existing Work Order? Choose whether the connector should check for existing work orders. The default is No. Options include:
  • Yes—The connector will check for existing work orders of the same type that are not cancelled or closed. If a Distance value is provided (for example, distance is greater than 0), the connector will check for existing work orders specified within the distance of each new work order. This avoids creating new work orders in the same general location.
  • No—The connector will not check for existing work orders of the same type. NOTE: Choose yes only if the event has a valid value in the geometry tagged field. If a valid geometry value does not exist, an extent cannot be created to query for existing work orders. Distance (meters) (conditional) Specifies the distance from a new work order to check for existing work orders. If existing work orders are discovered within the specified distance, a new work order will not be created. If a distance less than 0 is specified, the connector will check for existing work orders without regard to location. The default value is 20. Parameter is shown when Check for Existing is set to Yes. Buffer WKID (conditional) The WKID of the projected spatial reference to use if your event's geometry is not already in a projected spatial reference. The default is World/Web Mercator 3857. Parameter is shown when Check for Existing is set to Yes. Update Cityworks Data? Choose whether the connector should update its cache of Cityworks data. The default value is No. Options include:
  • Yes—The connector will update its cache of Cityworks data. Only choose yes when you know data has changed on the Cityworks side and you need to update the data.
  • No—The connector will not update its cache of Cityworks data. Considerations and limitations There are several considerations to keep in mind when using the Cityworks Connectors:
  • To create a work order with geometry using the Cityworks output connector, the outgoing event must have a valid value in the geometry tagged field.
  • To use the Check for Existing feature of the Cityworks output connector, the outgoing event must have a valid value in the geometry tagged field. Without a valid geometry, no extent can be created to query for existing work orders. Troubleshooting The logs in GeoEvent Server can be used to evaluate performance and troubleshoot any issues you may encounter with the Cityworks Connectors. For more information on monitoring logs in GeoEvent Server, see Monitor logs. Loggers for the Cityworks Connectors
  • com.esri.geoevent.transport.cityworks.CityworksTransportBase–Log messages related to polling existing and creating new work orders.
  • com.esri.geoevent.adapter.cityworks.CityworksAdapterOutbound–Log messages related to adapting raw GeoEvents into the Cityworks JSON format.
  • com.esri.ges.adapter.genericJson.JsonInboundAdapter–Log messages related to adapting the polled Cityworks work orders in JSON format into GeoEvents. Logging configuration In general, the log messages created by the connector components (the adapter and transport) provides the following information.
  • TRACE–Provides detailed data processing logs related to processing flow, parsing data, and creating events.
  • DEBUG–Provides details on each event created as well as detailed error messages with stack traces.
  • INFO–Provides brief information on errors encountered when processing individual events.
  • WARNING–Provides information on issues affecting a transport or adapter that may impact data processing.
  • ERROR–Provides information on issues keeping a transport or adapter from initializing and running properly.
